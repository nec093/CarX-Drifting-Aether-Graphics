# 独自マップと世界の表現（設計）

状態：設計中。まだ実装していません。このドキュメントは、独自マップ（Mod マップ）を CarX 本来の限界を超えて大きく、軽く、現実に近い世界にするための計画です。決まったことはここを書き換え、実装したものは `docs/architecture` の該当ドキュメントへ移します。

## 目的

1. CarX ではできない巨大なマップ（数十 km 四方）を、今のマップと同じくらい軽く動かす。
2. 藪、草原、森のように草木を大量に置いても軽く動かす。
3. ネオン、街灯、看板などの光、草木の揺れや透け感を、今より豊かに表現する。
4. バンプ（凹凸）とテクスチャの繰り返し・つなぎ目を自然にする。
5. 季節、風、天気、時間の流れを持ち、現実に近い没入感を出す。
6. 当たり判定とパーティクルを、上の世界の表現と合わせて広げる。

## 前提と制約

- ゲームの実行ファイルとゲームのファイルは書き換えない。足すのは Aether Loader の Mod と、その設定やデータファイルだけ。
- 逆コンパイルしたゲームのコードはリポジトリに入れない。ゲームとの接点は Harmony のパッチと、Unity の公開 API で作る。
- ゲームの素材と他人のマップの中身は、リポジトリにも配布物にも入れない。マップへの追加情報は、別ファイル（上書きファイル）として持つ。
- 描画は Aether Graphics のネイティブレンダラー（DX12、自前のレンダーグラフ、DXR）が受け持つ。Unity 側に存在しない物（GPU が並べる草木、GPU のパーティクル）も、Aether が直接描ける。これがこの計画の土台。
- 当たり判定と物理はゲーム（Unity のコライダーと CarX の物理）が受け持つ。描画と物理は別の Mod に分ける。
- 設定は Aether Graphics の F10 の中に置く。

## 全体の分担

| 置き場所 | 受け持つこと |
|---|---|
| Aether Graphics（本体） | GPU 主導の描画、自動 LOD、テクスチャの自然化、光の表現、環境の状態（時刻・季節・風・天気）とそれに反応する描画、植生の描画、パーティクル |
| Aether World（新しい Mod） | 巨大マップの分割読み込み、座標の原点の移動、当たり判定（タイル、草木の周りだけ、路面の種類）、ゲームの物理とのやりとり（タイヤの接地、路面の種類、接触） |
| マップ作者向け SDK（Unity パッケージ） | マップの中に置くコンポーネント。植生の範囲、木の種類、路面の種類、ネオン、雪や水たまりの場所、タイルの区切り、マップの緯度と標準の季節。ビルド時にサイドカーファイルへ書き出す |
| 上書きファイル（マップごと） | 既存のマップを作り直さずに、上の情報を後から足す。F10 の中で編集でき、マップごとに保存する（Aether Parts の ADJUST と同じ考え方） |

Aether Graphics と Aether World は、互いが無くても動く。Aether World が無ければ巨大マップの分割読み込みと当たり判定の拡張が無いだけで、描画の機能は既存のマップにも効く。情報のやりとりは Aether.API（Aether Loader の共通 API）経由にする。

### データの流れ

```
マップ（Unity シーン） ── SDK のコンポーネント ─┐
                                              ├─→ 世界の記述（サイドカー / 上書きファイル、JSON とテクスチャー）
上書きファイル（F10 で編集） ─────────────────┘            │
                                                          ├─→ Aether Graphics：描画（植生、光、マテリアル、環境）
                                                          └─→ Aether World：読み込み、当たり判定、路面
環境の状態（時刻・日付・季節・風・天気） ── Aether Graphics が持ち、Aether.API で Aether World にも渡す
```

## 1. 巨大なマップを軽く動かす

### 描画（Aether Graphics）

- GPU 主導の描画：インスタンスと境界をすべて GPU のバッファーに置き、コンピュートシェーダーで視錐台と遮蔽（前フレームの深度から作る Hi-Z）のカリングをして、`ExecuteIndirect` で描く。CPU の負荷が物の数に比例しなくなる。今の CPU カリングとクラスター構築は、遠い将来は GPU へ移す。
- 自動 LOD：メッシュを読み込んだとき、ワーカースレッドで簡略版（三角形 50 %、25 %、10 %）を作る（meshoptimizer の簡略化。MIT）。距離と画面上の大きさで選ぶ。光線の構造（BLAS）にも遠い物は簡略版を使う。
- HLOD：遠いタイルの物をまとめた 1 つのメッシュとテクスチャーにする（SDK のビルド時に作る。既存マップでは上書きファイルの指定で読み込み時に作る）。
- テクスチャーのストリーミング：見えているミップだけを GPU に置く。大きいマップほど効く。将来の課題（Unity のテクスチャーストリーミングとの兼ね合いを調べてから）。

### 読み込み（Aether World）

- タイル：マップを一定の大きさ（例：256 m 四方）のタイルに分け、車とカメラの周りのタイルだけを読み込む。タイルは Unity の追加シーン（Additive）か Addressables。分割は SDK のビルド時に行う。
- 座標の原点の移動：原点から 10 km を超えると float の精度で物と影が揺れる。車が原点から一定距離（例：2 km）離れたら、世界全体を移して原点を車の近くに戻す。Aether Graphics の履歴（TAA、DLSS、NRD、光線の構造）には、移動量を伝えて一斉にずらす（リセットしない）。
- 遠景：読み込んでいないタイルは HLOD と地形の簡略版だけを描く。

### 確かめること

- 64 km² のテストマップで、今のガレージと同じ 60 fps、CPU のメインスレッド 4 ms 以内。
- タイルの読み込みでフレームが 25 ms を超えないこと（`get_performance` の 25 ms 超えの回数）。

## 2. 大量の草木を軽く動かす

### 描画（Aether Graphics）

- GameObject を作らない植生：植生の記述（密度マップ、種類ごとのメッシュ、配置ルール）から、GPU がタイルごとに草木を並べる。結果はタイルの GPU バッファーに置き、カメラが動いたときだけ並べ直す。
- カリングと LOD：インスタンスごとに視錐台と遮蔽でカリング。近くはメッシュ、中距離は簡略メッシュ、遠くはインポスター（八面体インポスター：いろいろな向きから撮った絵を 1 枚のテクスチャーに並べたもの）。LOD の切り替えはディザーで滑らかにする。
- 風：頂点シェーダーで揺らす。草は細かく、木は幹がゆっくり、枝と葉は位相をずらして。突風は風向きに流れるノイズで、草原を波のように渡る。
- 草のなびき：車の位置と速度を GPU に渡し、通った所の草を倒して少しずつ戻す（地面に沿った小さなテクスチャーに記録する）。
- 光線：草は光線の構造に入れない（影は光線の影で草同士を、シャドウマップで地面への影を）。木は簡略版を BLAS に入れる。パストレーシングでは近い木だけを本来の形で。

### 配置情報の出どころ

1. Unity Terrain の草木：マップの TerrainData（木のインスタンス、ディテールの密度）を Aether がそのまま読む。作者の手間が最小で、既存マップにも効く。Unity が描く分は止める。
2. SDK の植生ボリューム：作者が範囲、種類、密度、傾斜や高さの条件を指定する。
3. 上書きファイル：既存のマップに、範囲と種類を後から足す。

### 確かめること

- 100 万本の草と 10 万本の木で、植生の GPU 時間 2 ms 以内（4K、RTX 4070 Ti）、CPU は 0.2 ms 以内。

## 3. 光の表現

- 光る面が周りを照らす：発光するマテリアル（ネオン、看板、窓）を光源として扱う。多数の光源は、画素ごとに少数の光を選ぶ方法（ReSTIR DI：候補を重みで選び、前のフレームと近くの画素の選んだ光を使い回す）で、影も光線で付ける。
- 形のある光源：線光源（ネオン管、蛍光灯）、面光源（看板）、投影模様（クッキー：街灯の傘の模様、窓の格子）。
- 霧の中の光：街灯やネオンのにじみ、光の筋（今の体積フォグに点光源とスポットライトを足す）。
- 点滅とアニメーション：看板の点滅、流れる文字、切れかけた蛍光灯のちらつき（SDK と上書きファイルで指定）。
- ランプの影：実装済み（`lampShadows`）。多数の光源では ReSTIR 側の影に移す。
- パストレーシング：発光マテリアルを光源として直接サンプリングする。

## 4. 草木の表現

- 葉の透過光：逆光で葉が明るく透ける（薄い面の透過。マテリアルの厚みと透過色）。
- 季節：葉の色を季節の位置で変える（新緑 → 濃い緑 → 紅葉 → 落葉）。木の種類ごとに紅葉の色と落葉の有無を持つ。草は枯れ草の割合が変わる。
- 落ち葉：秋の地面に落ち葉を重ねる（デカールとパーティクル）。

## 5. バンプとテクスチャのつなぎ目

マテリアルごとの機能として本体に入れ、SDK のマテリアル設定か、上書きファイルでオンにする。マテリアルの名前規則での自動指定も用意する。

- 繰り返しの解消：Stochastic（Hex）タイリング。テクスチャーを六角形の格子で少しずつずらし回して混ぜ、同じ模様の繰り返しを見えなくする（Heitz と Neyret、Mikkelsen の方法）。
- ディテール法線：近くでだけ効く細かい凹凸の法線マップを重ねる。
- 視差遮蔽マッピング：高さマップで奥行きを出す（石畳、レンガ）。光線の構造には入れない（表示だけの凹凸）。
- 地形とのなじませ：高さによるレイヤーの混ぜ合わせ（砂利が石の隙間に入る）、置いた物と地形の接地部分のブレンド（深度を見て地形の色に溶かす）。
- デカール：汚れ、割れ、タイヤ痕、水たまりの縁。

## 6. 環境の状態（時刻・季節・風・天気）

Aether Graphics が 1 つの状態として持ち、すべての表現が同じ値を見る。今の時刻・太陽・雲・夜の仕組みを広げる。

| 項目 | 内容 | 影響 |
|---|---|---|
| 日付と緯度 | マップの緯度（SDK・上書きファイル）と日付 | 太陽の通り道と日の長さ（天文計算）、季節の基準 |
| 季節 | 日付から自動、または手動 | 葉の色、枯れ草、落葉、積雪 |
| 風 | 向き、強さ、突風の強さと頻度 | 草木、雲、霧、煙、パーティクル、雨の角度、旗 |
| 天気 | 晴れ、曇り、雨、雪、霧と、その移り変わり | 雲の量、光の強さ、路面、霧の濃さ |
| 路面の状態 | 天気に遅れて変わる（乾き → 濡れ → 水たまり → 乾く） | 反射、タイヤ痕、水しぶき、グリップ（Aether World 経由） |
| 時間の流れ | 止める、実時間に合わせる、早送り | すべて |

- 雨：濡れた路面（暗く、なめらかに、水たまりは鏡）、車体の水滴、窓の雨粒、降る雨（パーティクル）。水たまりの場所は地形の窪みから自動で決め、SDK と上書きファイルで直せる。
- 雪：上を向いた面に積もる（光線で上が開いているかを見て、屋根や木の下には積もらない）。積もる量は時間とともに増える。
- 霧：高さで濃さが変わる霧（谷にたまる朝霧）。
- 現実の天気に合わせる案：外部の天気サービスを使うことになるので、入れるかどうかは別に決める（入れる場合も既定はオフ、位置情報は送らずマップの緯度経度だけ）。

## 7. 当たり判定（Aether World）

- タイルの当たり判定：描画と同じタイルで読み込む。遠くは簡略化した判定、近くは細かい判定。
- GPU で描く草木の判定：Unity のコライダーが無いので、車の周り（例：半径 50 m）の木だけにその場でコライダーを置き、離れたら外す（使い回すプール）。何十万本あっても判定は数十本分。
- 判定の種類：木の幹や柱は硬い障害物。藪や背の高い草は抵抗（減速）だけで、描画側の草もなびく。
- 路面の種類：舗装、砂利、草、泥、雪、水たまり。グリップとパーティクルを変える。天気と季節（濡れ、積雪）で変わる。
- 将来：倒れるコーン、看板など壊れる物。
- ゲームとの接点：タイヤの接地点と路面の種類、車体の接触を Harmony パッチで受け取り、Aether.API で Aether Graphics にも渡す（パーティクルと草のなびきに使う）。どのクラスにパッチするかは調べてから決める（逆コンパイルした内容はリポジトリに入れない）。

## 8. パーティクル（Aether Graphics）

今のタイヤスモークの仕組みを、GPU で大量に扱えるように広げる。

| 種類 | きっかけ | 挙動 |
|---|---|---|
| 砂ぼこり・砂利 | 未舗装路や路肩（路面の種類） | 風で流れ、太陽と影に照らされる |
| 水しぶき・霧状の水 | 濡れた路面、水たまり | タイヤの後ろに巻き上がる |
| 草や葉 | 草むら、強い風 | 舞い上がる。季節で色が変わる |
| 火花 | 壁やガードレールとの接触 | 跳ね返り、周りを照らす（短い光源） |
| アフターファイア・排気 | エンジンの状態 | 一瞬の光源 |
| 雨粒・雪 | 天気 | 風の角度で降り、ライトに照らされる |

- 共通：GPU で発生、更新、並べ替え、描画。風と天気に反応。画面の深度で地面や壁に当たって跳ね返る。光源と影に照らされ、体積フォグの光の筋の中で見える。
- タイヤスモークも同じ仕組みに移す（今の見た目と重さを基準にする）。

## 9. マップ作者向け SDK と上書きファイル

- SDK：Unity パッケージ。コンポーネント（植生ボリューム、木の種類、路面の種類、光源の形と点滅、雪や水たまりの範囲、タイルの区切り、マップの情報）と、ビルド時にサイドカーファイル（JSON とテクスチャー）を書き出すツール。マップの Mod の中にサイドカーファイルを同梱する。
- 上書きファイル：`AetherLoader/config/nec093.aether.world/maps/<マップ名>/` に置く。サイドカーと同じ形式で、サイドカーの上に重ねる。F10 の編集画面（範囲を置く、種類と密度を選ぶ、マテリアルの機能をオンにする）で作る。
- 形式は版番号を持ち、古い版も読めるようにする。

## 進め方

| 段階 | 内容 | 終わりの条件 |
|---|---|---|
| 1 | 本体の土台：GPU 主導の描画（カリングと間接描画）、自動 LOD、テクスチャの自然化（Stochastic タイリング、ディテール法線） | 既存の重いマップ（oi）で CPU とフレーム時間が下がる。つなぎ目が目立たない |
| 2 | 環境の状態：日付と緯度の太陽、風、天気（雨、濡れた路面、霧） | F10 で季節・風・天気を変えられる。雨の路面が映り込む |
| 3 | 植生：Unity Terrain の草木を Aether が描く、風と季節への反応、インポスター | 100 万本の草で 2 ms 以内 |
| 4 | SDK と上書きファイル：形式を決め、植生、光（発光面、線光源、点滅）、路面の種類、雪と水たまりの範囲 | 既存マップに上書きファイルで森とネオンを足せる |
| 5 | Aether World：路面の種類と接地情報、草木の周りの当たり判定、パーティクルの拡張 | 砂利で砂ぼこり、濡れた路面で水しぶき、木に当たれる |
| 6 | 巨大マップ：タイルの読み込み、原点の移動、HLOD | 64 km² のテストマップで 60 fps |

各段階は、その段階だけで使える形で出す。順番は、既存のマップにすぐ効くものを先にしている。

## 未決のこと

- Aether World を独立した Mod にするか、Aether Graphics の中の別モジュールにするか（物理に触れるので分けたい）。
- 巨大マップのタイルを、Unity の追加シーンで作るか Addressables で作るか。CarX の Mod マップの読み込み方を調べてから決める。
- 植生の密度マップの解像度と、タイルあたりの上限。
- ReSTIR DI を入れる時期（光の数が多いマップができてからでよいか）。
- 現実の天気に合わせる機能を入れるか。
- SDK の配布形態（Unity のバージョン、CarX の Mod マップ制作環境との相性）。
